# 自动化与通知

本文维护故障切换、定时变更、域名到期和通知的流程语义。常驻 YAML 和恢复命令由[常驻程序指南](AGENT.md)维护；状态转换、周期和通知规则变化时同步本文。

## SDK 与常驻程序

`automation` 提供探测、状态转换和计划计算，`notify` 提供事件策略和渠道发送。Go 调用方提供任务配置、数据库、锁和调度。`dnsgo-agent` 将这些能力组合成独立循环，并用本地 SQLite 保存状态。

DDNS 的公网 IP 来源、变化判断和调度属于调用方；DnsGo 通过 DNS 记录读写接口供其实现。面板租户、权限和记录所有权也由接入项目控制。

## 健康探测

`automation.Probe` 支持 ping、TCP 和 HTTP(S)，结果包含 `Healthy`、`Latency` 与 `Reason`。未设置探测超时时默认使用 5 秒。

| 配置 | 用途 |
| --- | --- |
| `Target` | 主机名或 HTTP(S) URL |
| `IP` | 指定连接的目标地址，HTTP(S) 保留原 URL 的 Host 与 TLS 名称 |
| `Port` | TCP 端口 |
| `HTTPClient` / `ProxyURL` | 调用方提供的客户端和匹配代理配置 |
| `InsecureSkipVerify` | 显式关闭证书验证的诊断选项，正式配置优先保留校验 |

ping 依赖运行环境中的系统命令及权限。为探测配置代理时，`HTTPClient` 与 `ProxyURL` 需要对应；可选常驻程序负责根据 YAML 构造它们。

## 故障切换

| 模式 | 行为 |
| --- | --- |
| `pause` | 按探测结果暂停或恢复确定的 DNS 记录 |
| `value` | 在主值和备值之间更新记录 |
| `conditional` | 根据前置记录条件控制目标，由单独的条件切换入口处理 |

探测模式下，`Cycle=1` 在一次相反状态的观察后切换；`Cycle>1` 先累计计数，计数到阈值后的下一次同向结果才切换，因此 `Cycle=2` 需要 3 次。`Cycle` 表示计数行为，与探测间隔分别设置。

直接调用 SDK 时，保存返回的 `FailoverState`、记录 ID 和切换结果；重启前后的待写入意图由调用方协调。常驻程序会在写入前保存意图，首次从实际记录初始化主备位置；恢复时先回读，无法确认则进入人工核对状态。

`value` 模式根据新值选择 A、AAAA 或 CNAME，切换可能影响记录类型与 ID。再次操作时使用返回的 ID，并在测试域名验证同名其他记录与厂商约束。

## 定时 DNS 变更

支持一次、每日、每周和每月的启用、暂停、删除与改值计划。时间计算使用任务传入的时间和时区，调用方需要保持调度与记录状态一致。

- 每月不存在的日期跳过该月，例如 31 日计划不会溢出到下个月。
- 删除成功后任务结束，避免重复删除。
- 常驻程序写前保存意图，恢复时使用 `ReconcileDueSchedule` 回读。
- 恢复时目标状态不符或任务配置指纹变化，保留待核对状态，由人工确认下一步。

同一记录由多个任务控制容易互相覆盖。常驻配置拒绝两个故障切换或定时任务指向同一账号、Zone ID 和记录 ID；自建调度器需要自行实现相同的所有权策略。

## 域名到期提醒

`RegistrationLookup` 通过 RDAP 服务清单定位查询入口，并以 WHOIS 回退。到期日期缺失或网络失败时保留上次已知值，不能将查询失败直接记为域名未到期。

`DueExpiryGroups` 按配置天数分组，在传入时间的本地小时达到 09:00 后才生成提醒；同一域名有 20 小时冷却。通知成功后保存 `LastNotified`，避免重复发送。并非所有后缀的公开数据都能提供注册和到期日期。

## 通知与任务轮次

通知策略分别作用于故障切换、证书、域名到期三类事件，可选择全部、仅失败或关闭。渠道包括 SMTP、SendCloud、阿里云邮件、WXPusher、Telegram、QQ 机器人、群机器人和自定义 Webhook。

常驻 `run` 为故障切换、定时、证书、到期查询和通知建立独立循环，长时间签发不会阻塞探测；共享 DNS 账号的适配器调用串行保护。`once` 顺序执行一轮。通知失败保留待发送状态，实际送达以渠道结果和业务回读为准。

这些流程当前主要具有源码和本地检查证据，真实故障演练、通知送达、购买签发和目标部署的验证状态由[实施状态](IMPLEMENTATION.md)与[适配器验证记录](ADAPTER-COVERAGE.md)分别维护。
