# DNS 操作

本文维护跨厂商域名与记录的操作步骤及常见差异。公共签名和示例由 [SDK 接入指南](SDK.md)维护；名称、分页、RRset、能力或错误语义变化时同步本文。

## 发现域名与记录

`dnsgo.FindZone(ctx, provider, name)` 遍历未筛选的域名列表，并精确比较名称。中文域名与 Punycode 输入在发现阶段等价，比较忽略大小写和末尾根点；返回的 `Zone.Name` 和 `Zone.ID` 保留厂商表示。后续调用继续使用该对象。

`ListZones` 的关键词查询和 `ListRecords` 的主机名筛选可能由厂商做模糊匹配。需要定位一个确定主机名时，使用 `dnsgo.ListSubdomainRecords`；该入口逐页读取并按名称、类型和线路做精确比较。

| 输入 | 用途 |
| --- | --- |
| `example.com` | `FindZone` 的完整域名 |
| `www` | `RecordQuery.Name` / `ListSubdomainRecords` 的相对主机名 |
| `@` | 根域的相对主机名 |
| 厂商返回的 `Record.Name` | 更新时保留的名称表示 |
| `dnsgo.RecordFQDN(zone, record)` | 展示或比较时使用的完整名称 |

分页结果的 `Total` 与 `Items` 分别表示总量和当前页条目。不要把当前页当成全部记录；也不要因厂商本地筛选留下空页，就推断后续没有结果。公共精确查询会处理适配器的这类差异，大账号调用仍需设置超时和频率限制。

## 写入前检查能力

`Capabilities()` 声明适配器的源码能力，账号权限、套餐和域名状态仍会影响实际调用。`provider.MinTTL(ctx, zone.ID)` 与 `provider.RecordLines(ctx, zone.ID)` 用于读取目标域名的 TTL 和线路信息。

| 字段或能力 | 调用约定 |
| --- | --- |
| `RecordTypes` | 先确认记录类型，再准备该类型需要的值和优先级 |
| `MinTTL` | 静态默认信息；按域名查询的结果仍需核对 |
| `Lines` | 表示可选择非默认线路；仅返回默认线路时仍可读取线路列表 |
| `Remarks` / `Status` / `Weight` | 分别控制备注、启停和权重等可选写入 |
| `CreateZone` | 仅声明实现；账号还可能需要所有权验证或套餐权限 |

显式传入不支持的字段时，适配器返回 `CodeUnsupported`。调用方应展示能力限制或调整自己的任务，避免无条件重试。

## 更新一个确定的对象

1. 根据已保存的域名 ID 和记录 ID 调用 `GetRecord`。
2. 核对名称、类型、当前值和业务归属，确认仍是预期目标。
3. 在原对象上修改必要字段，保留 `Extra`、名称表示及 RRset 成员。
4. 调用 `UpdateRecord`，保留返回的记录 ID；厂商可能在更新后更换 ID。
5. 使用返回 ID 再次 `GetRecord`，逐字段核对期望状态。

SDK 中的最小片段只演示调用流程，完整的并发控制、记录所有权、审计与幂等策略由业务系统实现。

### RRset 与备注

Route 53、PowerDNS、华为云和青云等厂商可能在 `Record.Values` 中保留同一 RRset 的多个成员。`Value` 表示选中的逻辑值，不能仅设置一个新 `Value` 后丢弃原来的 `Values`，也不能无条件把整个集合改成单元素。

PowerDNS 的备注归属于整个 RRset，同名同类型的其他值共享备注。青云的备注属于整个主机，公共记录备注入口返回不支持；使用 `providers.QingCloudHostRemarks` 时要确认主机下全部记录的影响。细节及扩展接口见 [SDK 接入](SDK.md#可选厂商扩展)。

## 结果不明与删除

写入超时、连接中断或响应解析失败时，服务端可能已经完成操作。遇到 `CodeResultUnknown`，保存目标、请求意图和已知 ID，先读取厂商状态再决定下一步。直接重试创建、删除或整组写入，可能产生重复对象或扩大影响。

删除前确认操作范围：公共 `DeleteRecord`、阿里云扩展 `DeleteSubDomainRecords` 和青云 `DeleteHost` 的范围不同。后两类会影响整个相对主机名或主机下的记录集合。删除后的“不存在”应通过 ID 或精确查询确认；其他查询失败仍按原错误分类处理。

## API 回读与解析生效

| 层次 | 可以证明 |
| --- | --- |
| 写入响应 | 厂商接受或报告了本次操作 |
| 详情与列表回读 | 厂商管理 API 当前可见的记录状态 |
| 分配的权威 DNS 查询 | 权威服务器当前返回的名称、类型、值与 TTL |
| 递归解析器与业务访问 | 特定缓存和访问路径上的实际效果 |

这些结果需要分别记录。公共递归缓存可能仍保留旧值，本机代理也可能改变 DNS 结果。阿里云已完成的 API 与权威查询范围见[真实验证记录](ADAPTER-COVERAGE.md#2026-10-18-阿里云真实验证)，其他厂商按各自行的状态判断。
