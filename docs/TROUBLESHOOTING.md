# 故障排查

本文维护按错误和现象定位问题的步骤。错误码来源是根包 `errors.go`，实际厂商证据由[适配器验证记录](ADAPTER-COVERAGE.md)维护；错误分类或恢复路径变化时同步本文。

## 先确定失败阶段

先分别确认配置解析、网络连接、身份认证、资源授权、请求参数、厂商执行和独立回读。上一步成功只说明该阶段通过，不能据此推断后续阶段。

| 错误码 | 检查方向 | 后续操作 |
| --- | --- | --- |
| `invalid_input` | 凭据键、必填参数、名称、TTL 与类型字段 | 修正配置或输入后重新检查 |
| `authentication_failed` | 令牌或签名身份 | 在私有凭据系统中核对有效期和账号 |
| `permission_denied` | 资源范围、授权策略和套餐 | 核对目标账号对该资源的权限 |
| `unsupported` | 适配器能力、非默认线路或扩展接口 | 查看 `Capabilities()` 和厂商差异 |
| `not_found` | 域名、记录 ID、账号范围 | 精确发现域名并重新读取目标 |
| `conflict` | 并发修改、RRset 或备注冲突 | 回读原对象并重新判断业务意图 |
| `rate_limited` | 请求频率和厂商限制 | 按调用方退避策略降低并发和频率 |
| `transport_error` | DNS、代理、连接与 TLS | 检查网络路径；写入还需核对远端状态 |
| `result_unknown` | 写入可能已发生 | 保存意图与 ID，先回读再决定重试 |
| `provider_error` | 厂商业务拒绝或未细分响应 | 查看脱敏厂商错误码与请求 ID |

Go 代码使用 `dnsgo.IsCode` 判断类别，使用 `errors.As` 提取 `*dnsgo.Error` 的 `Provider`、`Operation`、`VendorCode` 和 `RequestID`。不要依赖 `Message` 的固定文本判断业务分支。

## 域名或记录查不到

1. 确认当前凭据所属账号，目标域名是否在该账号范围。
2. 用 `FindZone` 精确发现域名，保留返回的原始名称与 ID。
3. 使用相对主机名查询，根域用 `@`。
4. 检查分页；名称关键词筛选可能只返回模糊匹配或局部页面。
5. 记录 ID 在更新后可能变化，核对最近一次成功返回值。

中文域名的比较支持 Punycode 等价，但此约定只作用于公共域名发现。后续写入保留厂商对象，避免自己改写名称表示。

## API 已成功，解析仍是旧值

先通过 `GetRecord` 回读目标，再查询该域名分配的权威 DNS，最后核对递归缓存与实际业务访问。每一步记录查询来源、时间、名称、类型、值和 TTL。代理 DNS、本机缓存和仍在存活的旧 TTL 均可能影响结果，不能用单个本机查询代替全部生效验证。

## 阿里云的常见限制

- `InvalidRR.NoExist` 对应记录不存在，当前映射为 `CodeNotFound`。
- 建域返回 `Txt.Record.Expired` 时需要先满足所有权 TXT 验证；本项目现有验证没有证明成功建域。
- 显式权重范围为 1–100；A、AAAA、CNAME 的详情权重会通过列表补充，需要记录列表权限。
- URL 转发、线路、最低 TTL 和付费能力可能受到套餐限制。

这些结论限定于[已记录的实测范围](ADAPTER-COVERAGE.md#2026-10-18-阿里云真实验证)，账号政策变化时重新核对。

## 常驻程序停在待核对状态

先停止该实例的自动执行，确认厂商 DNS、订单和部署目标的实际状态，再使用 `inspect-*` 摘要和对应恢复命令。数据库、任务配置指纹和历史记录 ID 都属于恢复依据，应保留原件。

`check` 仅验证配置和适配器构造，成功不代表网络、授权或真实任务已通过。数据库旁 `.lock` 拒绝第二个执行进程时，先确认现有实例，避免启动多个调度器争用记录。命令与状态含义见[常驻程序指南](AGENT.md)。

## 提交问题

提供版本或提交号、Go 版本、厂商标识、调用阶段、错误类别、厂商错误码、请求 ID 和已执行的回读结果。示例使用保留域名与脱敏字段，删除令牌、签名、私钥、数据库、证书材料和原有业务记录。网络问题只记录代理类型及是否启用，隐藏代理凭据。
