# 适配器逐项验证记录

本文只记录 DnsGo 各适配器的实现与验证状态；上游静态配置和源码位置由[上游盘点](UPSTREAM-INVENTORY.md)维护，整体实施状态由[实施状态](IMPLEMENTATION.md)维护。更新某个适配器时，先核对对应上游源码和 Go 分支，再在本表补充实测日期、账号范围与结果。真实账号未执行时维持“尚未实测”，不能仅凭注册或编译改成已验证。

状态含义：`源码实现` 表示可构造且具有对应的 Go 调用流程；`接口静态对照` 表示上游与 Go 的名称、公共方法、产品分派及可识别 API 动作通过仓库内的结构检查，不能证明全部参数、返回字段或异步生效时机。复杂分支已按[实施状态](IMPLEMENTATION.md)中的具体记录补审，仍需在真实服务中确认。真实验证与源码状态分别记录；本表的“尚未实测”适用于对应行及产品分支，已经执行的能力另列证据边界。

### 2026-10-18 阿里云真实验证

时间使用 Asia/Shanghai。凭据由现有彩虹 DNS 数据库通过只读事务读取，经 SSH 直接传入本机验证进程内存；没有写入项目、证据或日志。验证调用本地 Go SDK，基于初版源码及下述两处修正，这些修正已收录于 `v0.1.1`。

| 范围 | 国科.网络 | edu2026.cn |
| --- | --- | --- |
| 验证前原有记录 | 5 条，分页大小 20，1 页 | 110 条，分页大小 20，6 页 |
| 账号检查、域名发现、完整记录读取 | 通过 | 通过 |
| 最小 TTL 与线路元数据读取 | 600 秒、13 条线路 | 600 秒、13 条线路 |
| A / AAAA / CNAME / TXT / MX 添加与独立详情回读 | 五种均通过 | 五种均通过 |
| 编辑主机名、记录值、TTL 600→900、备注；MX 优先级 10→20 | 五种均通过，旧名称的测试记录消失 | 五种均通过，旧名称的测试记录消失 |
| TXT 精确子域查询 | 通过 | 通过 |
| 编辑后权威 DNS | `dns11` / `dns12.hichina.com`，10 项均通过 | `dns3` / `dns4.hichina.com`，10 项均通过 |
| 临时记录清理与原有记录核对 | 全部清理，原有 5 条的完整 SDK 快照摘要一致 | 全部清理，原有 110 条的完整 SDK 快照摘要一致 |

共执行两轮，每轮仅在随机前缀 `dnsgo-verify-<随机值>-<类型>` 下创建、编辑并清理 10 条临时记录。修正后的完整轮次为 06:04:56–06:05:24；06:06:18 完成最终只读复核，两轮累计 20 个临时记录 ID 均返回 `CodeNotFound`，原有记录快照摘要保持一致。脱敏结构化结果、测试记录的权威响应和前后摘要见[真实验证证据](verification/2026-10-18-aliyun.json)。原有业务记录内容不进入该证据文件。

实测发现并修正：

- 阿里云删除后的详情读取返回 `InvalidRR.NoExist`，原来只按 HTTP 状态分类，导致误报普通厂商错误。现映射为 `CodeNotFound`；同类域名错误 `InvalidDomainName.NoExist` 也按[官方错误码](https://help.aliyun.com/zh/dns/api-alidns-2015-01-09-errorcodes)映射，但本次未主动制造缺失域名错误。408/5xx 仍优先保持 `CodeResultUnknown`。修正后所有测试记录的不存在状态通过真实回读。
- `FindZone` 原来无法将中文名称与对应的 Punycode 名称匹配。现在只在比较时统一 IDNA 表示，继续返回厂商原始 `Zone.Name` 与 `Zone.ID`。中文和 Punycode 两种输入均通过真实只读查询；后续记录操作沿用厂商返回名称。单元检查覆盖双向名称转换、大小写、末尾根点及相近域名不误匹配。

权威查询从服务器直接访问分配的阿里云 DNS，使用非递归请求并校验权威应答标志、记录名称、类型、值及 TTL 900 秒，20 项均一次通过。本机 DNS 有代理虚拟 IP 行为，不能作为独立解析证据；本次不宣称所有递归缓存均已收敛。

以上基础轮次没有测试非默认线路写入、启停、SRV/CAA/NS/URL、建域等能力，随后补测结果见下节；付费能力、故障注入、证书、部署、自动化和消费者集成仍未验证。Cloudflare 经维护者确认不在当前配置中，保持尚未实测。服务器应用配置、数据库记录和服务未变更，验证后彩虹 DNS 公网 HTTPS 返回 200。Go 1.24 的 `go test ./...`、`go vet ./...` 及三个清单检查均通过。

#### 扩展验证与 v0.1.1 修正

07:12:07–07:14:33（Asia/Shanghai）完成扩展轮次：两组账号各 41 项通过，共 82 项；两项新建临时托管子域的请求均被阿里云以 `Txt.Record.Expired` 拒绝，需要先满足所有权 TXT 验证条件，成功建域仍未验证。这两个拒绝保留原始失败状态，单列为厂商前置条件受限，不能计为通过；没有新建域名遗留。原始用例结果与判定说明见[扩展验证证据](verification/2026-10-18-aliyun-extended.json)。

| 权威生效 | 禁用 TXT、启用 TXT、通配符 TXT、SRV、CAA 在两台分配的权威 DNS 上，共 20 项额外检查通过 |

## 续写规则

- 只更新完成审查的行，保留未审查行的现状；每行实测记录应链接独立证据或注明可复现的账号范围、操作、日期及回读结果。
- 证书服务的 ACME 五类共享核心实现；需分别确认目录、EAB、验证、续期和撤销差异。云证书三类需分别确认订单费用、DNS 验证、下载和取消。
- 多产品部署目标按上游 `product` 选项逐分支审查；目标名称存在不能替代每个产品分支完成。
- 上游新增或删除入口时先更新上游盘点、Go 注册与本表，再调整 README 中的范围。
